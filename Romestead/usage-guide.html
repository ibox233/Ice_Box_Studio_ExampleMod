Romestead Localization API

A small BepInEx 6 dependency for Romestead mod authors. Register localized text once, use short keys in your mod, and let the API reapply strings after the game reloads localization data.

一个给 Romestead 模组作者使用的小型 BepInEx 6 依赖。注册一次本地化文本，在模组里使用短 key，并让 API 在游戏重新加载本地化数据后自动重新应用文本。

1. Install And Reference

  1. Install BepInEx 6 for Romestead.
  2. Install RomesteadLocalizationAPI.dll into BepInEx/plugins.
  3. Reference RomesteadLocalizationAPI.dll from your mod project.
  4. Add a BepInEx dependency to your plugin class.
[BepInDependency(RomesteadLocalizationAPI.PluginInfo.PLUGIN_GUID)]
public sealed class MyPlugin : BasePlugin
{
    public override void Load()
    {
    }
}

2. Quick Start

Create one small localizer holder in your mod. This binds every lookup to your plugin GUID, so you do not have to pass the GUID every time.

using RomesteadLocalizationAPI.Api;

namespace MyMod;

internal static class I18n
{
    public static readonly RomesteadLocalizer L =
        RomesteadLocalization.For(PluginInfo.PLUGIN_GUID);
}

Register your localization in Load(). For packaged mods, read external files from the DLL directory.

using System.IO;
using System.Reflection;
using BepInEx.NET.Common;

public sealed class MyPlugin : BasePlugin
{
    public override void Load()
    {
        var pluginDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location);
        I18n.L.RegisterJson(Path.Combine(pluginDir, "Localization.json"));

        var title = I18n.L.Text("mod.name");
        Log.LogInfo(title + " loaded.");
    }
}

Thunderstore and r2modman may install your mod into a generated plugin folder. Do not rely on Paths.PluginPath + PluginInfo.PLUGIN_NAME for external files in packaged mods.

3. Single JSON File

The recommended format for most mods is one file with languages at the top level.

{
  "en": {
    "mod.name": "My Mod",
    "mod.description": "Adds a useful feature.",
    "items.count": "{0} items"
  },
  "zh_CN": {
    "mod.name": "我的模组",
    "mod.description": "添加一个实用功能。",
    "items.count": "{0} 个物品"
  },
  "zh_TW": {
    "mod.name": "我的模組",
    "mod.description": "加入一個實用功能。",
    "items.count": "{0} 個物品"
  },
  "ja_JP": {
    "mod.name": "My Mod",
    "mod.description": "便利な機能を追加します。",
    "items.count": "{0} 個のアイテム"
  }
}
var pluginDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location);
I18n.L.RegisterJson(Path.Combine(pluginDir, "Localization.json"));

var text = I18n.L.Text("items.count", 5);

4. Multiple JSON Files

If translators prefer separate files, put one language per JSON file. The file name is the locale.

Localization/en.json 
{
  "mod.name": "My Mod",
  "mod.description": "Adds a useful feature."
}
Localization/zh_CN.json 
{
  "mod.name": "我的模组",
  "mod.description": "添加一个实用功能。"
}
var pluginDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location);
I18n.L.RegisterJsonDirectory(Path.Combine(pluginDir, "Localization"));

5. Embedded Text

For a small mod with only a few strings, you can keep the text in C# and ship no JSON file.

I18n.L.RegisterTexts(
    (RomesteadLocales.English, "mod.name", "My Mod"),
    (RomesteadLocales.English, "mod.description", "Adds a useful feature."),
    (RomesteadLocales.ChineseSimplified, "mod.name", "我的模组"),
    (RomesteadLocales.ChineseSimplified, "mod.description", "添加一个实用功能。"));

You can also register one language at a time.

I18n.L.RegisterTexts(RomesteadLocales.English, new Dictionary<string, string>
{
    ["mod.name"] = "My Mod",
    ["mod.description"] = "Adds a useful feature."
});

6. Using Text In Config And UI

Use I18n.L.Text(key) anywhere you need display text.

private static string Text(string key)
{
    return I18n.L.Text(key);
}
Enabled = Config.Bind("General", "Enabled", true, new ConfigDescription(
    Text("config.enabled.description"),
    null));

For UI that needs to react to language changes, subscribe to LanguageChanged.

I18n.L.LanguageChanged += OnLanguageChanged;

private void OnLanguageChanged(string locale)
{
    title.Text = I18n.L.Text("window.title");
}

7. Key Scope And Fallback

You can safely use short keys such as mod.name and entry.enabled. The API internally stores them as Your.Plugin.Guid.mod.name, so two mods do not overwrite each other.

Fallback order:

  1. Current game language.
  2. English.
  3. Simplified Chinese.
  4. Any registered text for that key.
  5. The key itself.

Locale aliases such as zh, zh_Hans, zh-Hans, and zh_CN are normalized to the same internal code.

2. 快速开始

在模组里创建一个很小的本地化持有类。它会把所有读取绑定到你的插件 GUID，这样后续不用每次手动传 GUID。

using RomesteadLocalizationAPI.Api;

namespace MyMod;

internal static class I18n
{
    public static readonly RomesteadLocalizer L =
        RomesteadLocalization.For(PluginInfo.PLUGIN_GUID);
}

在插件 Load() 里注册本地化文件。发布打包模组时，外置文件应从 DLL 所在目录读取。

using System.IO;
using System.Reflection;
using BepInEx.NET.Common;

public sealed class MyPlugin : BasePlugin
{
    public override void Load()
    {
        var pluginDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location);
        I18n.L.RegisterJson(Path.Combine(pluginDir, "Localization.json"));

        var title = I18n.L.Text("mod.name");
        Log.LogInfo(title + " loaded.");
    }
}

Thunderstore 和 r2modman 可能会把模组安装到包管理器生成的插件目录。打包发布的模组不要依赖 Paths.PluginPath + PluginInfo.PLUGIN_NAME 来查找外置文件。

7. Key 隔离与回退

可以放心使用 mod.name、entry.enabled 这类短 key。API 内部会把它们存成 Your.Plugin.Guid.mod.name，所以不同模组不会互相覆盖。

文本回退顺序：

  1. 当前游戏语言。
  2. 英文。
  3. 简体中文。
  4. 该 key 下任意已注册文本。
  5. key 本身。

zh、zh_Hans、zh-Hans、zh_CN 这类别名会被归一化到同一个内部代码。
